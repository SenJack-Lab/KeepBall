# KeepBall

通用的 Android「套壳保活」工具：把任意应用**收起成一颗悬浮小圆点**（不占地方，视觉上如同最小化窗口），点按小圆点立即还原；目标应用在收起期间驻留后台。

> 目标体验：应用收起后只占一个图标大小的位置，点击即回到原样——类似 PC 上把窗口最小化到任务栏/托盘。

## 为什么需要它

Android 的「最小化」（Home 键/手势）只是把应用切到后台，系统随后会：

- 按 Cached / Empty 进程优先级**杀掉**它（内存压力下几乎必杀）；
- Android 12+ 的 Cached Apps Freezer 会把后台应用**冻结**（cgroup freezer），来电、推送等响应都会延迟。

KeepBall 的目标就是对抗这两点，并给出「收起成小圆点」的交互。

## 方案总览（本仓库将容纳多种方案）

| 方案 | 目录 | 原理 | 不被杀 | 不被冻结 | 门槛 |
|------|------|------|--------|----------|------|
| v1 悬浮球 + 电池白名单 | `app/`（当前默认） | 公开 API：悬浮窗 + 回桌面 + 用户点击豁免启动；申请电池优化豁免 | 大幅降低概率 | ❌（12+ 仍可能冻结） | 无 |
| v2 Shizuku | `plan/`（规划中） | shell 权限：关 App Freezer / 开自由窗 / 调窗口尺寸 | ✅ | ✅（可关冻结器） | 需 Shizuku（adb 授权一次） |
| v3 小窗化 | `plan/`（规划中） | 把目标应用真塞进极小自由窗/分屏，窗口可见即真前台 | ✅ | ✅（真前台进程） | 系统 UI 支持；缩放有下限 |

### 方案对比要点

- **没有任何公开 API 能把不可见的应用标记为前台**。进程 adj/冻结由系统按「窗口是否真的在屏幕上」判定，方案 2/3 是仅有的两条真路径。
- v1 是零门槛基线：收起后目标应用仍在后台，点球即还原；配合电池白名单在日常场景下已不易被杀，但 Android 12+ 可能冻结它。
- v3（小窗化）体验最接近「系统认为它在前台」的本意，但窗口有最小尺寸限制，缩不到一颗图标大小，且被全屏应用覆盖时会退回后台。
- v2（Shizuku）可以两全：用 shell 权限把窗口缩到极小并关闭冻结器，代价是用户多一次 adb 授权。

## v1 使用流程

1. 授予「显示在其他应用上层」（悬浮窗）权限；
2. 选择要驻留的应用（会自动打开它），正常使用；
3. 下拉通知点「停止」前，先回 KeepBall 点「收起驻留应用」→ 回到桌面，屏幕边缘出现小圆点；
4. 点小圆点 → 应用还原到前台；
5. 建议点「申请电池白名单」进一步降低被杀概率。

## 构建

Android Studio 直接打开工程；或命令行 `./gradlew assembleDebug`。
minSdk 26（Android 8.0）· targetSdk 34 · 纯 Java、零第三方依赖。

## 权限说明

- `SYSTEM_ALERT_WINDOW`：显示悬浮球；
- `QUERY_ALL_PACKAGES`：应用选择器列出全部可启动应用；
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`：申请电池优化豁免（系统弹窗，用户确认）；
- 前台服务（`specialUse`）：维持悬浮球常驻。
